# 图表开发工具

D2 的设计围绕一个目标：**让工程师享受绘制图表的过程**。很多工具声称对于简单图表可以做到这一点，但一旦遇到稍微复杂一些的图表——那些最需要被创建的图表——体验就不再好了。

为什么会这样？因为当今大多数图表工具是设计工具，而非开发工具。它们给你一个空白画布和拖放工具栏，就像你在 Figma 或 Photoshop 上看到的那样，并将其预期工作流程视为设计过程。工程师不是视觉设计师，缺乏对系统进行空间布局的能力，不应成为创建有价值文档的障碍。每次拖放都无需提前规划，更新也不该沦为移动元素、调整大小以腾出空间的令人沮丧的过程。Declarative Diagramming（声明式图表）消除了这种摩擦。

在 Hashicorp 推出 Terraform 让工程师以文本形式定义基础设施之前，他们都是在 AWS 和 Google Cloud 控制台中通过点击来配置的。如今，那已显得不够专业了。审核流程、回滚操作、历史记录和版本控制在哪里？很难相信全球公司视觉文档的未来会主要由拖放设计工具构成。
